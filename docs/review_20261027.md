## A. Not in place

### A1. club_cli has no application commands  `[ ]`

**Where:** club_cli `client/club_client/cli.py`;
`client/tests/test_endpoint_contract.py:53`.

**Problem:** No command for any of the 15 `/v1/applications` operations
or for GET/PUT `/v1/system/preferences/profile_options`. 17 operations
missing. README line 4 claims full parity.

**Fix:** Add commands for all 17 operations, including every optional
parameter. Update README.

**Test:** `test_every_server_operation_is_covered` passes with
`cli_test.conf` cloning club_server main. `CLAIMED_BY_OPEN_ISSUES` stays
empty.

### A2. CLI test confs do not turn the new modules on  `[ ]`

**Where:** club_cli `cli_test.conf:33`, `cli_test_modules_off.conf`.

**Problem:** Neither conf sets `extended_profile_enabled` or
`applications_enabled`. The "all modules on" stack starts with both off.
`cli_test_modules_off.conf` also has
`identity_verification_required=false`, which makes applications 503
even when its flag is on.

**Fix:** In `cli_test.conf` set both keys true and
`identity_verification_required=true`. Leave the off conf off.

**Test:** `/v1/capabilities` on the `cli_test.conf` stack returns
`extendedProfile: true, applications: true`.

### A3. ihm beta and prod turn modules on but deploy 1.2.0  `[ ]`

**Where:** deploy_servers `ihm/product.conf:26`.

**Problem:** beta and prod clone club_server `beta_release` / `release`,
still at 1.2.0 (fcdafb4). Pydantic ignores the two unknown settings.
`/v1/capabilities` has neither flag. deploy_apps builds club_client
`beta_release` / `release` at 4c99a4e, which has no UI. Nothing records
1.3.0 as the minimum for these keys.

**Fix:** Either promote server and client branches together before
turning the flags on for beta/prod, or set the flags false there until
promotion. Record the minimum server version next to the keys in the
conf.

**Test:** After `just deploy beta`, `/v1/capabilities` on the beta host
returns both keys. The beta app shows the Applications sidebar entry.

### A4. club_client VERSION still 1.2.0  `[ ]`

**Where:** club_client `VERSION:1`; club_cli `VERSION`; club_sdk
`pubspec.yaml`.

**Problem:** main carries the feature built against server 1.3.0 but
reports 1.2.0. A bug report quoting the app version cannot tell a
pre-feature build from this one.

**Fix:** Bump to 1.3.0 in all three when the release is tagged. If a dev
build goes out before that, bump now.

**Test:** The generated ihm dev app reports 1.3.0 in its About / version
output.

## B. Server

### B1. Layout fingerprint ignores profile options  `[ ]`

**Where:** club_server `services/application_catalogue.py:65`.

**Problem:** The stored layout is measured with the club's position
checkboxes, but the fingerprint covers only labels, clauses and fonts. A
later PUT `profile_options` never re-measures.

**Fix:** Include the profile options document (or its hash) in the
layout fingerprint, so a change invalidates the stored layout.

**Test:** Publish a template with 0 positions. PUT 40 positions. GET
`/applications/{id}/form` for a member. Expect either a re-measured
layout that fits, or 422 `APPLICATION_DOES_NOT_FIT`. Must not draw the
signature row over the footer. Check page 1 ends above 794 pt.

### B2. Stale layout falls back to per-member layout  `[ ]`

**Where:** club_server `services/application_downloads.py:141`.

**Problem:** When the stored layout cannot be re-measured,
`_current_layout` returns None and `choose_layout` runs per member from
that member's answers. The layout stops being the template's (R18). A
member can get 422 on a GET.

**Fix:** When the stored layout is stale and cannot be re-measured,
refuse with one clear error for the admin (template needs re-save), not
a per-member fallback.

**Test:** Publish a template using a clause. Remove that clause from
`clauses.json`. GET form for a member with a long address and one with a
short address. Both must get the same layout, or the same error.

### B3. Generic preferences route bypasses the 503 gate  `[ ]`

**Where:** club_server `services/club_info.py:35`.

**Problem:** `EXTENDED_PROFILE_DISABLED` is attached only to PUT
`/system/preferences/profile_options`. PUT
`/admin/preferences/profile_options` with a valid body stores it.

**Fix:** Apply the same gate on the generic admin preferences route for
this key. Also confirm `SystemPreferenceService.write` runs
`validate_profile_options_value` there (not checked in this review).

**Test:** With `EXTENDED_PROFILE_ENABLED=false`, super admin PUT
`/v1/admin/preferences/profile_options` with a valid document. Expect
503 `EXTENDED_PROFILE_DISABLED`.

### B4. Custom term refs are never resolved  `[ ]`

**Where:** club_server `services/application_text.py:171`.

**Problem:** A custom term's heading and body are copied raw, not passed
through `text()`. A `ClauseRef` or `FactRef` there (allowed by schema and
R6) stays unresolved. Save refuses it as incomplete.

**Fix:** Pass term heading and body through `text()` like other fields.

**Test:** PATCH
`terms=[{"heading": {"fact": "venue"}, "body": {"clause": "rule.no_fee"}}]`.
POST `/save`. Expect 200. Preview prints the resolved text.

### B5. Preview demo member can be ineligible  `[ ]`

**Where:** club_server `services/application_rules.py:102`.

**Problem:** `preview_member` corrects the demo birthday only against
`born_on_or_before`. A first category with `born_on_or_after` after
15 June makes the demo member too old.

**Fix:** Pick the demo birthday inside the first category's full band
(after `bornOnOrAfter`, before `bornOnOrBefore`).

**Test:** `ageCategories=[{label, bornOnOrAfterUtc: 2010-09-01}]`. GET
`/applications/{id}/preview` as admin. Expect 200, not 422
`APPLICATION_NOT_ELIGIBLE`.

### B6. Wrong language named in APPLICATION_INCOMPLETE  `[ ]`

**Where:** club_server `services/application_form.py:44`.

**Problem:** The error always names `languages[-1]`. When English is the
one missing it names the other language.

**Fix:** Report the language whose text is actually missing, per field.

**Test:** `languages=['en','mr']`, `title={'mr': 'x'}`, all else
complete. POST `/save`. Expect 422 with `missing: ['title']`,
`language: 'en'`.

### B7. Backfill reads CLUB_TIMEZONE from the environment only  `[ ]`

**Where:** club_server `db/backfills/membership_date.py:29`.

**Problem:** `Settings` also reads from `secrets_dir`. A deployment that
supplies the time zone as a secrets file backfills with the default
zone. Same latent error as `age_eligibility`.

**Fix:** Build the backfill's time zone through `Settings`, not
`os.environ`.

**Test:** Provide `CLUB_TIMEZONE` only as a secrets file. Run the
migration on a request resolved at 2026-03-01 20:30 UTC. Expect the
membership date in that zone, not the default zone.

### B8. Position label needs no print language  `[ ]`

**Where:** club_server `schemas/extended_profile.py:36`;
`application_pdf_blocks.py:185`.

**Problem:** A label needs one language, not English or any print
language. A form draws an empty checkbox label.

**Fix:** Require an English label. On save, refuse a template whose
print languages lack a label for any position.

**Test:** PUT `positions=[{value: 'fwd', label: {'hi': 'फॉरवर्ड'}}]`.
Expect 422. Or, if accepted, save of a template printing `['en']`
expects 422 naming the position.

### B9. Devanagari shaping across font fragments  `[ ]`

**Where:** club_server PDF drawing (fpdf2 fallback fonts).

**Problem:** Not checked. uharfbuzz is not in the local .venv. Conjuncts
that cross a fallback-font fragment boundary may break.

**Fix:** Install uharfbuzz in the test venv. Add a PDF test with
Marathi text containing conjuncts mixed with Latin.

**Test:** Render the PDF, extract text, compare with the input string.

## C. SDK

### C1. ApplicationPatch doc wrong for null languages  `[ ]`

**Where:** club_sdk `lib/sdk/models/application_patch.dart:16`;
club_server `services/application.py:168`.

**Problem:** Doc says a `languages` getter returning null resets to
English only. Server skips null and leaves the list unchanged.

**Fix:** Pick one. Either the server treats null as reset, or the SDK
doc says null means no change and callers send `['en']`.

**Test:** `updateApplication(id, ApplicationPatch(languages: () => null))`
on a bilingual template. Returned template matches the doc.

### C2. Unknown fact type throws for the whole response  `[ ]`

**Where:** club_sdk `lib/sdk/models/application_fact_type.dart:34`.

**Problem:** `fromWire` throws `FormatException` inside
`ApplicationFact.fromMap` and `ApplicationClause.fromMap`. One unknown
type breaks `listApplications`, `getApplication`, `getClauses`.
Callers catching `ServerException` do not catch it.

**Fix:** Add an `unknown` value, or skip the one fact and keep the rest.

**Test:** Feed a list response with one fact of type `"x"`. Expect the
other templates to parse.

### C3. Unknown status maps to draft  `[ ]`

**Where:** club_sdk `lib/sdk/models/application_status.dart:23`.

**Problem:** Any unknown wire value becomes `draft`. The app then offers
edit and Save, and the server answers 422 with no hint.

**Fix:** Add an `unknown` value. The app treats it as read-only.

**Test:** Parse status `"archived"`. Expect `unknown`, not `draft`.

### C4. No SDK stack has both features on together  `[ ]`

**Where:** club_sdk `sdk_test.conf`, `sdk_test_modules.conf:36`.

**Problem:** `sdk_test.conf` runs applications with
`extended_profile_enabled=false`. `sdk_test_modules.conf` turns the
extended profile on but `identity_verification_required=false` makes
every `/applications` route 503. The joins (profile options on a form,
guardian block and `spreadWithGuardian`, `membershipDateUtc`) are never
tested.

**Fix:** Set `identity_verification_required=true` in
`sdk_test_modules.conf`, or add a third conf. Add tests for the three
joins.

**Test:** `just test-modules` runs at least one applications test that
prints a member's `preferredPosition` label.

### C5. SDK CLAUDE.md and justfile describe the old conf split  `[ ]`

**Where:** club_sdk `CLAUDE.md:128`, `justfile:9`.

**Problem:** Text still says `sdk_test.conf` is "optional modules off"
and `test-modules` is "credits, evaluations, marketing on". Applications
is on in `sdk_test.conf` and 503 on the modules stack.

**Fix:** Rewrite both lines to list which modules each conf turns on.

**Test:** Read the two lines against the two conf files.

## D. Client

### D1. Download does nothing on mobile browsers  `[ ]`

**Where:** club_client `cl_club_app/lib/src/application_routes.dart:301`;
`open_pdf_bytes_web.dart:20`; also `review_routes.dart` (pre-existing).

**Problem:** Every handler is `unawaited(openPdfBytes(bytes))`, which
drops the bool for a blocked popup. `window.open` runs after an awaited
download, which mobile browsers treat as not user-initiated. No toast,
no file. The Linux suite runs the io variant, so this is untested.

**Fix:** Await `openPdfBytes`. On false, show a toast with a link or a
fallback (download via anchor click, or open the blob in the same tab).

**Test:** On Android Chrome and iOS Safari, tap Download on the waiting
page and on Applications. Expect the PDF to open or a visible message.

### D2. CSP may blank the blob PDF tab  `[ ]`

**Where:** club_client `club_project_generator/lib/src/web_files.dart:64`
(comment at 46); `test/parts_test.dart:161` pins `object-src 'none'`.

**Problem:** `blob:` is allowed only in img-src, media-src, worker-src.
The new tab navigates to a blob document and inherits the opener's
policy including `object-src 'none'`. The comment claims PDFs are
covered. Not verified in a browser.

**Fix:** Check in Chrome, Firefox and Android Chrome against a generated
ihm build. If the tab is blank, add the needed directive and update the
test and the comment. If it works, write the result into the comment.

**Test:** Open a generated web build, tap Download, see the PDF in the
new tab in all three browsers.

### D3. Applications master does not refresh after an identity upload  `[ ]`

**Where:** club_client
`cl_remote_store/lib/src/providers/applications_master.dart:47`.

**Problem:** The master watches the capability, the current user and the
manual refresh only. The server returns an empty list until a document
is uploaded. After upload the list still shows the hint.

**Fix:** Also watch `clIdentityDocsMasterProvider` (or bump a version
on upload).

**Test:** Widget test: active member without a document opens
Applications (hint shown), uploads a document, returns. Expect the
Download row without a Refresh.

### D4. Extended-profile onboarding step lost on reload  `[ ]`

**Where:** club_client
`cl_member_onboarding/lib/src/models/onboarding_routes.dart:101`.

**Problem:** The step is allowed only while `extendedProfile == true`.
While capabilities load, `allowedOnboardingPaths` excludes the path and
the fallback sends the member to welcome. The submit-documents step
stays open while the capability is unknown.

**Fix:** Treat an unknown capability like the document step does: keep
the path allowed until the value arrives, then redirect if false.

**Test:** Unit test on `allowedOnboardingPaths` with capabilities
loading: `/onboarding/extended-profile` is allowed. With `false`: not
allowed.

### D5. Onboarding screen refuses with a hand-written ErrorView  `[ ]`

**Where:** club_client
`cl_member_onboarding/lib/src/screens/onboarding_extended_profile_screen.dart:181`.

**Problem:** CLAUDE.md says a non-role gate refuses with
`AccessDeniedView`, never a hand-written `ErrorView`. The screen uses
`ErrorView('Not available')`, copied from the submit-documents screen.

**Fix:** Use `AccessDeniedView`. Fix the submit-documents screen the
same way.

**Test:** Widget test: a registered member on the route sees
`AccessDeniedView`.

### D6. Toaster used after await without a mounted check  `[ ]`

**Where:** club_client
`cl_club_admin/lib/src/widgets/profile_options_card.dart:505`.

**Problem:** `save()` captures `ShadToaster.of(context)` before the
await and uses it after. Every other section card checks `mounted`.

**Fix:** Check `mounted` after the await before showing the toast.

**Test:** Widget test: dispose the card while the PUT is pending. No
exception in debug.

### D7. Profile options section hidden on a failed read  `[ ]`

**Where:** club_client
`cl_club_admin/lib/src/views/club_identity_view.dart:434`.

**Problem:** The section renders only when `profileOptionsProvider` has
a value. A network error or 5xx hides it with no message and no retry.

**Fix:** Render an error state with Retry when the provider has an
error.

**Test:** Widget test: provider in error. Expect the section with an
error message and a Retry action.

### D8. Initials take a UTF-16 code unit  `[ ]`

**Where:** club_client
`cl_club_applications/lib/src/widgets/admin_application_list.dart:723`.

**Problem:** `applicationTitle(template)[0]` takes one code unit. A
leading emoji or a non-BMP character gives a lone surrogate.

**Fix:** Use `characters.first` from the `characters` package.

**Test:** Unit test with a title starting with an emoji. Expect the
whole emoji as the initial.

### D9. Status compared as a string  `[ ]`

**Where:** club_client
`cl_club_applications/lib/src/utils/application_title.dart:452`.

**Problem:** `publishedApplications` compares
`t.status.wireName == 'published'` through a local constant instead of
`t.status == ApplicationStatus.published`.

**Fix:** Compare with the enum. Delete the constant.

**Test:** `dart analyze` clean. Existing tests pass.
